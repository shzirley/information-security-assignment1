# VELTRIX frontend direction

Source: the user's [brand identity board](<../docs/references/Veltrix Secure Brand Identity Board.png>), [GSM](../docs/design/VELTRIX_GSM_v0.1.md), and [product PRD](../docs/prd/VELTRIX_BankKYC_PRD.md). Product: synthetic bank-onboarding evidence management and an isolated academic cipher lab. Audience: applicants, assigned reviewers, operational admins, and evaluators.

This direction stays alongside the frontend code. Supporting [component references](../docs/design/REFERENCES.md) and the [historical UI audit](../docs/verification/ANTISLOP_QA.md) are grouped under `docs/`.

Design Read: a case-based KYC workspace using the supplied folded-V/keyhole identity, Midnight Blue, and Royal Blue. Landing ENERGY 3 / RHYTHM 3 / MOTION 2; workspace ENERGY 2 / RHYTHM 2 / MOTION 1. The hero rotates evidence nouns without a visible pause button or footnote, following the user's clarified request. The scroll-linked evidence sequence retains the supplied reference direction with reduced-motion support.

- Midnight Blue navigation anchors the workspace; Cloud and white surfaces keep forms and comparison tables readable.
- One blue accent marks the primary action or selection; green and amber are functional status colors.
- Montserrat expresses the supplied logo/heading character; Inter provides readable form/nav/body text. Fira Code is retained only for bytes, numeric results, and hex samples.
- A repeated section index and three aligned cipher labels express the product's archive and comparison tasks.
- Dashboard uses a case ledger, explicit next action, and a preparation checklist; progress follows evidence completeness rather than arbitrary activity metrics.
- Panels group related records, rather than presenting each feature as a marketing card.
- Buttons use 6px radii, panels 12px, and status labels 4px to distinguish actions, containers, and metadata.
- Whitespace separates the page action, records, and supporting explanations. Compact numeric rows keep comparisons scannable.
- File, folder, upload, download, lock, and chart icons explain the adjacent action/content. They are not brand assets.
- A reusable BrandLogo combines a reference-derived SVG folded V/keyhole and Montserrat wordmark; initial avatars do not invent profile photography. SVG reconstruction is documented separately from original master artwork.
- Royal Blue/Indigo/Cyan gradients are limited to the supplied layered symbol identity. Tracked uppercase is limited to the supplied wordmark/tagline rather than generalized to UI labels.
- The hero rotates identity/document/evidence nouns in a fixed-height line at full opacity, while its accessible heading stays stable. There is no visible pause button or hero footnote. Hover or keyboard focus within the hero pauses rotation; offscreen/hidden tabs suspend it. The scroll sequence assembles four evidence categories into one application, with native scrolling and anchors.
- Motion never gates reading or form interaction. Live reduced motion renders the headline and evidence sequence in their static alternatives.
- Landing composition alternates an asymmetric application preview, an evidence sequence, a numbered submission flow, and a permissions ledger. Each addresses a distinct product question.
- Operational review shows category, size, version, and completeness only. Applicant names, file names, previews, and plaintext never appear in reviewer/admin responses.
- Lab comparison uses a readable table with units, algorithm labels, and an explicit simulation boundary; no measured series is claimed for static illustration values.
- Light and dark themes share semantic tokens. Theme choice is user-controlled.
- All fixtures, cipher samples, and timings are labeled simulated. No security or performance claim is made from mock data.
- Evidence tiles are deliberately equal because all four categories are submission requirements, not marketing feature rankings.
- The application preview alone has a soft elevation and slight desktop rotation to distinguish an illustrative case sheet from the real interactive workspace.
- Arrow icons mark navigation to a destination or a next wizard step; confirm, cancel, theme, upload, and decision controls use direct labels.
- Status labels encode the actual state machine and synthetic/demo boundaries; they do not imply security certification.
- A fingerprint glyph marks the academic discussion of identity privacy, not a biometric verification capability.
- Public copy describes KYC tasks, account roles, and data limits. Implementation labels such as FE, backend, and mock API belong in developer documentation. The topbar has no development-mode badge; synthetic-only, temporary-storage, and unmeasured-result notices use plain language where relevant.
- Academic/task labels, repeated simulation qualifiers in operational status labels, and fixture-login shortcuts were removed at the user's request. Login requires credentials; role comes from the session response. Laboratory results still identify simulations and usage notices still explain current data limits.
